Software & Automation

Five compact Python prototypes plus this Flask-served HUD demonstrate input validation, local metrics, dry-run planning, deterministic responses, and repository inventory.

Demonstrated scope

  • Dependency-free Python command-line scripts
  • Flask routes for static pages, health, inventory, deterministic responses, and review-only previews
  • HTML, CSS, and JavaScript HUD interactions
  • Dry-run file planning and local host/disk summaries
  • Automated API, route, inventory, and link checks

Current limitations

These are learning prototypes, not a production platform. There is no model integration, authentication, persistent proposal state, hosted deployment, background task execution, or automatic file modification. The REST example is a local record-construction function rather than an HTTP service.

Projects

  • Alfred Assistant Prototype — Routes text commands to a small deterministic response table; it has no model, wake word, speech engine, or system-task execution.
  • Personal Dashboard Data Prototype — Prints local host and disk metrics as JSON; it is not a Flask/FastAPI dashboard and does not fetch weather.
  • File Automation Toolkit — Builds a dry-run organization plan from files in a directory without moving, renaming, compressing, or syncing them.
  • REST Record Prototype — Validates item inputs and returns an owner-scoped dictionary; it has no HTTP server, database, JWT, or CRUD routes.
  • Portfolio Inventory Utility — Scans a supplied directory and reports its HTML page names; the Flask HUD in the repository root is the actual website.
