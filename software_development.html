Software & Automation Labs

The Alfred local-assistant flagship and four compact Python labs demonstrate typed API design, approval-gated desktop safety, input validation, local metrics, dry-run planning, and repository inventory.

Demonstrated scope

  • Dependency-free Python command-line scripts
  • Flask routes for static pages, health, inventory, deterministic responses, and disabled-by-default session-owned proposal metadata
  • HTML, CSS, and JavaScript HUD interactions
  • Dry-run file planning and local host/disk summaries
  • Automated API, route, inventory, and link checks

Primary work

Alfred AI Assistant is now a separate loopback-only FastAPI service with cited website knowledge, optional Ollama integration, safe inspection, and typed desktop actions that cannot execute without an exact preview and explicit approval. The original Software Automation/alfred-ai-assistant prototype remains intact as legacy evidence.

Current limitations

The four labs are learning prototypes, not production systems. Alfred is local-only, desktop execution is disabled by default, and every enabled mutation or launch still requires per-action approval. There is no hosted Alfred service, general autonomous control, voice assistant, wake word, durable personal memory, or email/calendar integration.

Labs & Prototypes

  • Personal Dashboard Data Prototype — Prints local host and disk metrics as JSON; it is not a Flask/FastAPI dashboard and does not fetch weather.
  • File Automation Toolkit — Builds a dry-run organization plan from files in a directory without moving, renaming, compressing, or syncing them.
  • REST Record Prototype — Validates item inputs and returns an owner-scoped dictionary; it has no HTTP server, database, JWT, or CRUD routes.
  • Portfolio Inventory Utility — Scans a supplied directory and reports its HTML page names; the Flask HUD in the repository root is the actual website.
