Primary Work // Local AI & Desktop Safety

Alfred AI Assistant

A native, loopback-only household-manager assistant that answers with cited evidence, can optionally use local or compatible reasoning providers, and cannot alter or launch anything until the operator reviews an exact preview and explicitly approves that single action.

FastAPI + Pydantic SQLite audit state Typed desktop skills Provider + research boundaries

Problem and users

General desktop agents are impressive but often hide the most important details: what they can read, what a model actually supplied, what will change, and whether a conversational phrase counts as permission. Alfred is designed for one local Windows operator who wants useful portfolio knowledge, current research, system summaries, and a small set of desktop conveniences without surrendering control.

Implemented by me

  • A separate typed FastAPI service that rejects public binding and is intentionally excluded from public Render and Docker services
  • An original, versioned British household-manager persona: discreet, concise, candid about uncertainty, gently dry, and safety-first
  • A curated website index over fixed first-party evidence paths, with repository-relative citations and instruction-neutralization
  • Optional Ollama and generic OpenAI-compatible reasoning providers with bounded structured messages, timeouts, visible model status, and explicit deterministic fallback
  • Keyless Wikipedia research plus optional Brave Search, normalized dated citations, provenance labels, and SSRF-hardened fixed-source HTTP
  • Read-only system, disk, directory-metadata, and process summaries that omit environment dumps, file contents, secrets, and command lines
  • Typed proposals for folder creation, one-file move/rename, bounded extension organization, allowlisted app launch, allowlisted HTTPS URL launch, and optional clipboard text
  • Owner/session isolation, high-entropy bearer authentication, expiring payload-bound approvals, atomic single-use execution, collision denial, path revalidation, and append-only audit events
  • An accessible responsive local console showing provider, web, index, health, citations, exact previews, approval state, expiry, execution result, and audit history

Architecture

  1. Local console
    typed input + explicit approval
  2. FastAPI policy layer
    auth, schemas, ownership
  3. Knowledge / research / actions
    separate bounded tools
  4. SQLite + Windows APIs
    audit and approved effects

The public Flask portfolio only showcases Alfred. It does not proxy or expose the desktop-control API. The local service listens on 127.0.0.1:8020; chat and research orchestration remain separate from typed action execution, so model text cannot become a command.

Safety boundary

Every desktop mutation, application launch, URL launch, or clipboard write follows: propose → render exact effects and root-relative path diff → approve the canonical payload hash → execute once → record the immutable result. There is no chat shortcut, blanket approval, delete action, recursive operation, overwrite default, raw shell, PowerShell, arbitrary executable, or user-supplied command argument.

Paths reject traversal, absolute/UNC/device forms, and links or reparse points that resolve outside configured roots. Execution revalidates paths, filesystem state, URL/app allowlists, ownership, expiry, and stored-payload integrity immediately before claiming the action. Residual local-account and filesystem-race risks are documented in the threat model.

Knowledge and research

Portfolio answers search a bounded index built only from fixed repository evidence sources and return their paths. Research mode consults keyless Wikipedia and, when separately configured, Brave Search. Outbound research permits HTTPS on the standard port, validates DNS and redirects against private, loopback, metadata, reserved, link-local, and multicast destinations, and limits time, bytes, content types, redirects, excerpts, and result counts.

Retrieved text is labeled as untrusted data in the provider prompt. It cannot alter Alfred's persona, action policy, or approval rule. Responses disclose whether they used deterministic composition, website evidence, web retrieval, or a configured model; provider failure never masquerades as an AI answer.

Trade-offs

  • Native Windows execution is required for desktop skills; omitting Alfred from containers avoids a misleading or unsafe deployment story.
  • A fixed knowledge manifest and fixed research providers are narrower than arbitrary RAG or browsing, but they make provenance and SSRF controls reviewable.
  • A shared local action token plus per-tab session ownership is intentionally simpler than accounts; it is suitable for one trusted local operator, not a remote multi-user service.
  • Typed actions sacrifice general automation in exchange for inspectable payloads, deterministic validation, and meaningful approval.

Tests

The dedicated suite covers configuration and sanitized status, migrations, API/UI contracts, persona behavior, website citations, provider failures and timeouts, web provenance, prompt-injection handling, SSRF and redirect denial, secret/process redaction, traversal/UNC/link escape, collisions, allowlists, approval ownership, expiry, payload tampering, replay, two-client isolation, disabled execution, and mocked launches. Filesystem mutations are limited to temporary approved roots.

Current Limitations

Alfred is local-only and not generally autonomous. No hosted desktop API, arbitrary browsing, arbitrary commands, deletion, screen/mouse/keyboard control, wake word, product voice pipeline, personal semantic memory, email/calendar integration, tray app, signed installer, background service, or startup persistence is implemented. Wikipedia is a narrow reference source; broad/current search requires an operator-supplied Brave key. Model quality depends on the explicitly configured Ollama or compatible endpoint. Approval and path confinement reduce risk but do not sandbox malware already running as the same Windows user.

Next milestones

The staged plan prioritizes Windows reparse/race hardening, token rotation and revocation, transactional skill recovery, citation-faithfulness evaluation, opt-in inspectable memory, push-to-talk before wake words, least-privilege integrations, and a signed native package with no surprise persistence. Completion criteria and non-goals are maintained in ALFRED_STATUS.md.
