Algorithms & Quality

Original Python implementations across data structures and algorithm strategies, backed by deterministic edge-case tests and explicit complexity trade-offs.

View algorithm source

Problem and users

Reviewers need concrete evidence of algorithm reasoning and test design that is independent of frameworks or external services. This lab gives learners and interviewers readable implementations, stated complexity, failure behavior, and tests that cover more than happy paths.

Architecture

  1. Typed Python inputs
  2. Data structure or strategy
  3. Deterministic result or explicit error
  4. Pytest normal + edge assertions

The module has no network, filesystem, clock, database, or random state. That deliberately small boundary keeps behavior deterministic and lets tests focus on contracts, ordering, mutation, complexity assumptions, and failure modes.

Trade-offs and implementation

  • Hash-based two_sum and sliding-window unique substring use additional memory to avoid quadratic scans
  • A queue built from stacks provides amortized O(1) operations, with occasional O(n) transfers
  • The binary search tree is intentionally unbalanced and rejects duplicates
  • BFS returns deterministic shortest paths only for unweighted edges
  • Merge sort is stable and O(n log n), but allocates O(n) additional space
  • Backtracking permutations materialize factorial output; dynamic-programming coin change returns a count, not selected coins

Run and verify

Run from repository root:

python -m pip install -r requirements.txt
python -m pytest algorithms-quality\tests -q
python -m ruff check algorithms-quality

The suite maps tests to arrays/strings, maps, stacks/queues, trees, graphs, sorting, searching, recursion/backtracking, and dynamic programming. See the quality report for test boundaries.

Security and reliability

The project accepts in-process values only and performs no I/O, so it has no secret, authentication, or network surface. Reliability comes from deterministic contracts, explicit invalid-input behavior, mutation-safety assertions, and tests that do not depend on external state.

Current Limitations

These educational implementations do not replace optimized standard-library or production packages. Generic ordering is expected but not runtime-enforced, the tree can degrade to O(n), the graph is unweighted, and permutation output becomes impractical quickly. No benchmark claim is made.
