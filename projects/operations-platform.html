Batcomputer Operations Platform

A separate FastAPI modular monolith for tenant-isolated operational assets, workflows, immutable audit evidence, and approval-pending Alfred intents.

View source on GitHub Open configured demo

Problem and users

Small internal operations teams need one accountable place to track assets and work across software automation, defensive security, IT support, data, network/platform, and quality engineering. Admins manage workspaces and users; operators create and advance work; viewers receive read-only access. The project demonstrates those boundaries without claiming enterprise identity or integration features that do not exist.

Implemented by me
API, schemas, persistence, migration, security boundaries, audit behavior, operator UI, tests, and operations documentation.
Strongest evidence
Cross-workspace denial, role enforcement, guarded state transitions, and same-transaction audit records.
Demo status
Runs locally. No hosted deployment is claimed; a demo link appears only when an HTTPS URL is configured.

Architecture

  1. Operator browser UI
  2. FastAPI routes and Pydantic validation
  3. Auth, RBAC, workspace scope, workflow rules
  4. SQLAlchemy + PostgreSQL or local SQLite

Mutations and their audit events commit in the same database transaction. The modular-monolith choice keeps authorization, tenant scope, and audit rules visible and testable instead of introducing distributed-service boundaries before they are needed.

Security and reliability

  • Argon2 password hashes and expiring signed access tokens
  • Server-side admin/operator/viewer checks and workspace filters on domain reads and mutations
  • Bounded pagination, typed validation envelopes, correlation IDs, JSON request logs, liveness, and readiness
  • Production startup rejects the documented development secret and non-PostgreSQL database URLs
  • Alfred intents remain approval-pending with executed=false; there is no provider call or execution path

Trade-offs

Short-lived bearer tokens keep the first implementation understandable but cannot be revoked before expiry. Synchronous request handling and a single relational service favor consistency and traceability over independent scaling. SQLite supports fast local evidence; PostgreSQL is required by production configuration for concurrency and operational safeguards.

Run and verify

Run from repository root:

python -m pip install -r requirements.txt
Copy-Item .env.example .env
Set-Location platform
python -m alembic -c alembic.ini upgrade head
python -m uvicorn app.main:app --reload

Open http://127.0.0.1:8000; OpenAPI is at /docs, liveness at /health/live, and dependency readiness at /health/ready.

Test evidence:

Set-Location platform
$env:PLATFORM_ENVIRONMENT = "test"
$env:PLATFORM_DATABASE_URL = "sqlite:///./migration-check.db"
python -m alembic -c alembic.ini upgrade head
python -m pytest tests -q
Set-Location ..
python -m ruff check platform

The API suite covers authentication, RBAC, tenant isolation, CRUD, workflow rules, immutable audit access, input validation, health/readiness, OpenAPI, and Alfred non-execution.

Current Limitations

There is no hosted deployment, password reset, refresh-token revocation, MFA, SSO, rate limiting, background execution, external integration, audit retention/export job, object storage, or generated/executed Alfred content. These are explicit backlog items rather than current capabilities.
