02 // Data and simulation flagship

Orbital Data Lab

A deterministic educational two-body simulation service that compares RK4 and velocity-Verlet, preserves scenario lineage, and makes numerical limits explicit. It is not flight grade.

View orbital source Open configured demo

Problem and users

Learners and technical reviewers need a reproducible way to compare numerical integration behavior without confusing an educational model for mission software. Users submit bounded initial conditions, inspect trajectories and energy drift, compare integrators, save content-addressed scenarios, and export results.

Implemented by me
Physics core, Pydantic API, persistence and lineage, exports, canvas UI, tests, and limits documentation.
Strongest evidence
Known circular-orbit behavior, energy-drift comparison, deterministic output, idempotent storage, and bounded validation.
Demo status
Runs locally. No hosted deployment is claimed; a demo link appears only when an HTTPS URL is configured.

Architecture

  1. Browser canvas or API client
  2. FastAPI + bounded Pydantic scenario
  3. RK4 / velocity-Verlet physics core
  4. Trajectory response + content-addressed SQLite

Simulation functions are deterministic and isolated from storage. Scenario identifiers derive from normalized content, so repeated writes are idempotent; schema and algorithm versions provide useful lineage without claiming signed build provenance.

Trade-offs and reliability

  • Input bounds include a 20,000-step ceiling to constrain memory and response time
  • Tests compare drift and final state across two integrators rather than treating one numerical method as universally superior
  • SQLite keeps the evidence service easy to run and inspect, but it is not intended for concurrent distributed ingestion
  • Full trajectory responses favor transparency and visualization over streaming very large simulations
  • Missing scenarios and invalid parameters return explicit API errors

Run and verify

Run from repository root:

python -m pip install -r requirements.txt
Set-Location orbital-data-lab
python -m uvicorn orbital_lab.api:app --reload --port 8010

Open http://127.0.0.1:8010. The service exposes a browser visualization and API documentation; liveness is at /health/live and database readiness at /health/ready.

Test evidence:

Set-Location orbital-data-lab
python -m pytest tests -q
Set-Location ..
python -m ruff check orbital-data-lab

The suite covers circular-orbit behavior, energy drift, determinism, bounds, API behavior, content-addressed idempotence, lineage, JSON/CSV exports, and missing records.

Current Limitations

The model is fixed, two-dimensional, point-mass central gravity. It omits perturbations, atmosphere, finite burns, relativity, body rotation, ephemerides, frame transformations, uncertainty, collision detection, and event handling. Passing one idealized circular-orbit test does not validate other regimes, navigation, mission planning, or safety decisions.
